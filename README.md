# 炼金材料监控抢购程序

> 三角洲行动 · 交易行（典藏外观）全自动监控与抢购 · iOS / Appium

用一台 Mac + 一台 iPhone，全自动完成「筛选皮肤 → 加入收藏 → 蹲点 → 抢购 → 循环」。
基于 **Appium + WebDriverAgent**，不越狱、不注入、不修改游戏客户端。

> ⚠️ **免责声明**：本项目仅供个人学习自动化技术使用。使用第三方工具操作游戏可能违反游戏用户协议，存在账号风险，请自行评估。作者不对任何封号、损失负责。

## 一、它做什么

```
① 采集：进入「典藏外观」，筛选赛季/品阶，把符合条件的皮肤逐个点开
        ├ 读成色 S(0.xxxxxx) —— 唯一身份
        ├ 读「X分Y秒后解锁」
        └ 点★收藏（关注列表）
② 抢购：进入「我的关注」，逐格扫描
        ├ 发现剩余 7~45 秒的 → 就地驻守
        ├ 解锁前 5 秒：主按钮 4 下开弹窗 → 停 0.3 秒 → 约 123 下狂点
        └ 收尾：关弹窗 → 刷新 ×2
③ 循环：关注里没货了 → 自动回市场重新采集 → 继续抢
```

游戏机制（实测）：公示期结束的瞬间按钮变绿，**约 0.5 秒内**有限名额被抢完，之后是随机抽签。

## 三、安装

```bash
# 1. 依赖
npm i -g appium
appium driver install xcuitest

# 2. 编译 OCR 守护进程（macOS Vision，读屏幕上的成色和倒计时）
swiftc -O ocrl.swift -o ocrl

# 3. 登记设备
mkdir -p .runtime
cp devices.example.json .runtime/devices.json   # 填入你的 UDID
node scan-devices.mjs                            # 或自动扫描已连接的 iPhone

# 4. 首次连接（会签名、安装、启动 WebDriverAgent）
#    首次需要在手机上「信任」证书：设置 → 通用 → VPN与设备管理
node check.mjs
```

## 四、快速开始

```bash
# 只采集
node collect3.mjs

# 只抢购（需先在游戏里停在「我的关注」页）

# 无限循环（抢 → 没货 → 采 → 再抢）
```

## 五、参数总表

> 所有参数都在文件顶部，改完需**重启对应进程**才生效。

### 5.1 抢购 `raidb.mjs`

| 参数 | 默认 | 作用 | 调整建议 |
|---|---|---|---|
| `NEAR` | `45` | 窗口上限（秒）：剩余 ≤45 秒才追 | 想更宽就调大，但太宽会让每轮扫描变慢 |
| `seconds > 7` | `7` | 窗口下限（秒）：太近的来不及 | 设备慢/网络差就调大（8~10） |
| `startAt = unlockAt - 5000` | `5` 秒 | 提前多久开始下发 | **最关键**。见下方调参 | 
| 主按钮次数 | `4` | 开弹窗的连点次数 | 打不开就加，误关就减 |
| 弹窗内停顿 | `300` ms | 主按钮点完等弹窗动画 | 动画慢的机型调到 400~500 |
| 狂点次数 | `123` | 连点总次数 | 决定覆盖时长 |
| 狂点间隔 | `hold 20 + wait 33` | 名义 53ms，**实测约 65ms/下** | 见下方"速度"说明 |
| 每格等待 | `250` ms | 点击后等面板刷新 | 读错率高就加到 350 |
| 翻屏滑动 | `0.82 → 0.305` | 一次滑 2 行（4 件） | 用下面的方法实测校准 |
| 翻屏后等待 | `900` ms | 等滚动停稳 | 列表长/惯性大就加到 1100 |
| 刷新次数 | `2` | 每次抢完刷新几下 | 列表刷新慢就加到 3 |
| 到底刷新 | `10` 下 | 扫到底后一次性刷新 | 通常不用改 |

### 5.2 采集 `collect3.mjs`

| 参数 | 默认 | 作用 |
|---|---|---|
| **成色** | **S（0.xxxxxx）** | 只收 S 级，其他成色（A/B/C…）一律不收 |
| **价格上限** | **650 币** | 只收 ≤650 的；超过的跳过（不是整页停，只跳过那一张） |
| 赛季 | 王者之剑 | 每次强制重选，防止筛选被重置成"全部赛季" |
| 停止条件 | 价格超限 或 列表到底 | 没有件数/屏数上限 |
| 翻屏滑动 | `0.82 → 0.305` | 一次 2 行（4 件） |
| 每格等待 | `320` ms | 点击后等面板 |
| 赛季 | 王者之剑 | 每次强制重选（防止筛选被重置） |
| 入口定位 | OCR 标题 | 按左侧列表里读到的标题位置点击，不写死坐标 |

## 六、按你的环境调参（重点）

### 6.1 提前量 `startAt`

**这是影响成功率最大的参数。** 它取决于三件事：

```
① 你的设备点击延迟（越狱 <10ms / 安卓 ADB 50ms / iPhone WDA 约 450ms）
② 从下发请求到第一下真正落地的时间
③ 你读到倒计时到实际解锁之间的误差（±1 秒）
```

调节方法：

```
看日志里这一行 → 下发结束 ...（相对解锁 +X.XXs）
    X 经常是负数（还没到零点就点完了）→ 提前量太大，调小
    X 经常大于 3（零点过了才点完）    → 提前量太大？不，是狂点太短，加次数
    零点没被覆盖到                    → 提前量调大
```

推荐流程：先用 `5` 秒跑 10 枪，看日志里 `相对解锁` 的分布，把"结束时刻"调到 **解锁后 2~4 秒**。

### 6.2 连点速度

名义间隔 `hold + wait` 与实际间隔**不是线性关系**（驱动会压缩 pause）：

| 名义 `wait` | 实测 |
|---|---|
| 30 | 62ms |
| 33 | 65~68ms |
| 39 | 64ms（反而更慢，噪声范围） |

结论：**这颗驱动基本锁在 60~70ms/下**，想控总时长就调**次数**，别调间隔。

```
目标覆盖 T 秒 → 次数 ≈ T / 0.065
```

### 6.3 滚动距离校准

不同机型/分辨率下滑动距离不同。校准方法：

```bash
# 1. 回到列表顶部
# 2. 记下第 1-4 格的成色
# 3. 滑一次，再看第 1-4 格
# 如果新第 1 格 = 旧第 5 格 → 正好前进 4 件（2 行）→ 距离合适
# 前进少了 → 加大距离；多了 → 减小
```

### 6.4 屏幕坐标

所有坐标都是**归一化 (0~1)**，按 iPhone 横屏逻辑分辨率换算，通常不需要改。
如果你的机型布局不同（比如刘海/灵动岛），用截图量一下按钮中心再改 `CELLS` / `MAIN` / `DLG`。

## 七、循环与自愈

`loop.sh`：

```
抢购 → (关注里前 3 格都读空 → 4 秒内退出) → 采集 → 再抢 → ...
每阶段前跑 check.mjs 体检，会话失效自动重建
单阶段失败重试 3 次（间隔 10 秒）
```

`dev.mjs` 自带**会话自愈**：任何请求报会话类错误，会自动 POST 一个新 session 并重试原请求。

覆盖不到的情况（需要人工介入）：

| 情况 | 处理 |
|---|---|
| WDA 证书过期（7 天） | 插线 → `node check.mjs` 重签 → 手机上信任 |
| 手机锁屏 | 设置自动锁定为「永不」 |
| Appium 记着已消失的 App | 杀掉 appium 后重新 `check.mjs` |

---

## 八、已知限制

1. **进队列成功率**：实测 iPhone + WDA 单次点击约 450ms，而窗口只有 0.5 秒，所以到得偏晚。想显著提升需要换平台（安卓 ADB 约 50ms）。
2. **判定不可靠**：抢完弹窗会自动消失，读不到状态时日志里的 `❌` 可能是误报，**以游戏画面为准**。
3. **每 7 天重签**：免费 Apple ID 的证书有效期 7 天，过期必须插线重签。
4. **一台手机一个游戏账号**：同账号多设备会互踢，跑机器人时不能同时玩。
